# Майор + Игрик

Игрик самостоятельно ведёт каталог игр, лобби, права участия и игровой прогресс. Для первой совместной задачи выберите, открывает ли Майор каталог или предлагает запуск конкретной игры из чата. Зафиксируйте вход, ожидаемый экран, привязку к чату, если она нужна, и поведение при отсутствии прав. Контракт передачи контекста определите перед реализацией выбранного сценария.

## Владельцы и код

- Если задаче нужна точка входа в Майоре, найдите её по выбранному сценарию и проверьте правила навигации. [Продуктовые решения Майора](../miniapp-product-decisions.md)
- Игрик отвечает за авторизацию и допуск, состояние лобби и ход игры. Для каталога начните с `apps/miniapp/src/app.tsx`. Для приглашения из группы и проверки подписанного контекста начните с `apps/api/src/max-bot/max-lobby-invite.ts`. Инструкции владельца и запуск описаны в `AGENTS.md` и `README.md` Игрика.

## Локальная проверка

Работайте в отдельном дереве Игрика. Проверьте каталог в деморежиме по `README.md`. В PowerShell с установленными зависимостями из корня Игрика можно запустить его локальный Vite.

```powershell
$env:VITE_DEMO_MODE = 'true'
npm.cmd run dev:miniapp
```

Для каталога найдите `apps/miniapp/test/catalog-navigation.test.tsx`, для лобби — `apps/miniapp/test/game-lobby-api.test.ts`. Сценарий с подписанным контекстом или правами проверяйте отдельно на локальных фикстурах. При изменениях сохранённого состояния подключайте соответствующие проверки Игрика с изолированным PostgreSQL 17 по его `AGENTS.md`.

## Совместимость и выпуск

Для Игрика используйте его отдельный рабочий процесс. Порядок выпуска двух сторон имеет смысл после согласования сценария и формата перехода. Если новый вход требует поддержки в Игрике, сначала проверьте совместимый принимающий путь и отказ для неподходящего входа. После этого проверяйте переход из Майора на ожидаемой паре версий.
