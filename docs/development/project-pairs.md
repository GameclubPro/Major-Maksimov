# Майор Максимов и соседние проекты

Назовите пару и результат в первой строке задачи. Например, «Майор + Караван — исправь открытие магазина из чата». «Биржа» и «Биржик» обозначают один проект. Для задачи одного продукта открывайте вторую сторону, когда её затрагивает вызов или пользовательский сценарий.

| Пара                                        | Что проверяем на границе                                                                                       |
| ------------------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| [Майор + Караван](project-pairs/karavan.md) | Переход из конкретного чата к его магазину и доступ после смены прав.                                          |
| [Майор + Биржа](project-pairs/market.md)    | Открытие карточки выбранного сообщества и управление рекламной кнопкой. Обмен статистикой имеет свой контракт. |
| [Майор + Игрик](project-pairs/igrik.md)     | Игрик работает самостоятельно. Совместная задача начинается с выбора сценария перехода.                        |

## Как начать задачу

1. Откройте карточку, прочитайте `AGENTS.md` обеих сторон и найдите вызов, обработчик и проверку, которая подтверждает нужный результат.
2. Сверьте пути, ветки, рабочие изменения и полные SHA исходных копий. Для зарегистрированных пар проверьте, откуда берёт базу `workspace`. Она может отличаться от папки, открытой в Codex. При расхождении выберите исходную ревизию по задаче и проверьте отличия до правок. [Настроенный workspace и владение рабочим деревом](agent-machine-contract.md#configured-workspace-and-ownership)
3. Используйте отдельное рабочее дерево каждой изменяемой стороны. Если достаточно правки в одном репозитории, второй остаётся источником контракта и проверок. Параллельные задачи ведите в отдельных рабочих деревьях Майора.
4. Сначала проверьте изменённую сторону, затем пользовательский сценарий на границе. Для изменения протокола проверьте пару версий, которая будет работать в переходный период. Используйте локальные фикстуры и одноразовые реальные хранилища для сценариев, зависящих от базы или очереди.
5. В итоге задачи укажите пару, обе ревизии, результат проверок, ссылки на правки и открытые шаги. Выпуск и приёмку отражайте по правилам каждого владельца.

Инструменты используют тот же список пар, профилей и первичных проверок. [Машиночитаемая карта](project-pairs/pairs.json)

Обновляйте карточку при изменении контракта. Личные пути, текущие SHA, настройки регистрации и состояние проверок храните в локальной записи задачи.
